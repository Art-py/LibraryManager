# План завершения JWT-аутентификации

Цель: завершить этап `v0.1`, добавив проверку выданных токенов, получение текущего пользователя, выход и обновление токенов.

## 1. Хранилище access-токенов

- [ ] Добавить получение access-токена пользователя из Redis.
- [ ] Проверять совпадение предъявленного access-токена с сохранённым, а не только наличие ключа.
- [ ] Обновить тесты `TokenRepository`: получение существующего и отсутствующего токена, совпадение и несовпадение токенов.
- [ ] Зафиксировать модель сессий: текущая схема `user_uid -> access_token` допускает только одну активную сессию пользователя.

## 2. Проверка JWT

- [ ] Добавить декодирование JWT с проверкой подписи и срока действия.
- [ ] Проверять тип токена: `access` или `refresh`.
- [ ] Валидировать `sub` как UUID пользователя.
- [ ] Добавить исключения для отсутствующего, просроченного и некорректного токена.
- [ ] Покрыть успешные и ошибочные сценарии модульными тестами.

## 3. Текущий пользователь

- [ ] Реализовать FastAPI dependency `get_current_user`.
- [ ] Получать access-токен из cookie `LM_user_access_token`.
- [ ] Сверять токен с Redis.
- [ ] Загружать пользователя из PostgreSQL и проверять состояние учётной записи.
- [ ] Добавить `GET /api/v1/users/me` и объявить его раньше `/{user_uid}`.
- [ ] Добавить интеграционные тесты защищённого эндпоинта.

## 4. Выход

- [ ] Добавить `POST /api/v1/auth/logout`.
- [ ] Удалять access-токен из Redis.
- [ ] Удалять access и refresh cookies из ответа.
- [ ] Возвращать `204 No Content`.
- [ ] Добавить интеграционные тесты выхода и повторного доступа.

## 5. Обновление токенов

- [ ] Добавить `POST /api/v1/auth/refresh`.
- [ ] Проверять refresh-токен, его тип, подпись и срок действия.
- [ ] Выпускать новую пару access/refresh токенов.
- [ ] Заменять access-токен в Redis и обновлять cookies.
- [ ] Определить и реализовать политику refresh rotation.
- [ ] Покрыть успешное обновление и ошибочные сценарии тестами.

## 6. Защита пользовательских данных

- [ ] Определить политику доступа к `GET /api/v1/users/{user_uid}`.
- [ ] Разрешить доступ владельцу записи и/или пользователям с подходящей ролью.
- [ ] Добавить тесты доступа без токена, с чужим токеном и с разрешённой ролью.

## Критерии завершения

- Все защищённые маршруты отклоняют отсутствующие, просроченные и отозванные токены.
- Logout действительно отзывает текущую сессию.
- Refresh-токен нельзя использовать как access-токен.
- `make check-code` проходит полностью.
- Поведение аутентификации отражено в Swagger и README.
